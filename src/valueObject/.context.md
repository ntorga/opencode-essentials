Branded value objects validate configuration, plugin inputs, and host-provided
TUI data before feature logic uses them. They cover identifiers, permissions,
OpenRouter credentials and model IDs, token counts, paths, and timestamps.
`idleTimeoutMs.ts` also bounds timer delays for idle compaction and the TUI
clock. Whole payloads, such as the state file, are parsed in `../documents/`.

## Summary

- absolutePath.ts — accepts absolute filesystem paths.
- absolutePath.test.ts — tests accepted and rejected path shapes.
- contextTokens.ts — validates positive ceilings to 2,000,000 and defines presets.
- contextTokens.test.ts — tests ceiling bounds and presets.
- featureId.ts — validates feature identifiers used in state and options.
- featureId.test.ts — checks accepted and rejected identifier shapes.
- featureStates.ts — validates boolean maps and creates a null-prototype map.
- featureStates.test.ts — tests accepted feature-state entries.
- idleTimeoutMs.ts — validates timeouts and clamps timer delays.
- idleTimeoutMs.test.ts — tests duration validation and timer-delay caps.
- messageId.ts — validates host message identifiers.
- modelId.ts — validates model identifiers with the shared model-token rule.
- modelId.test.ts — checks accepted and rejected model identifier shapes.
- modelRef.ts — validates and converts provider/model pairs.
- modelRef.test.ts — tests valid pairs and malformed pairs.
- openRouterApiKey.ts — trims and validates the OpenRouter API key.
- openRouterApiKey.test.ts — tests valid, missing, oversized, and unsafe keys.
- openRouterModelId.ts — validates OpenRouter provider/model IDs.
- openRouterModelId.test.ts — tests valid and malformed OpenRouter model IDs.
- permissionName.ts — validates permission names.
- permissionReplyMode.ts — validates the classifier reply mode (`once` or `always`).
- permissionReplyMode.test.ts — tests accepted modes and rejects `reject` and other shapes.
- permissionRequest.ts — validates pending permission request data.
- permissionRequest.test.ts — tests accepted and rejected request shapes.
- permissionRequestId.ts — validates permission request identifiers.
- providerId.ts — validates provider identifiers with the model-token rule.
- providerId.test.ts — tests valid and invalid provider IDs.
- sessionId.ts — validates session identifiers for URL path segments.
- sessionId.test.ts — tests accepted IDs and rejects unsafe path shapes.
- timestampMs.ts — validates epoch milliseconds from 2001 onward.
- timestampMs.test.ts — tests finite millisecond values and rejects seconds.
- tokenCount.ts — validates non-negative safe-integer token counts.
- util.ts — defines branded types, shared validation, record checks, and token patterns.

## Constraints

- Every external value MUST pass a constructor in this directory before it
  reaches business logic, a URL, a file write, or a JSON body.
- Input validator constructors take `unknown` and return a value or
  `undefined`; callers decide how to handle rejection.
- MUST NOT use classes; the branded type plus constructor is the value
  object.
- Identifier regular expressions MUST be anchored and bounded.

## Guidance

- Use `newValidated` in util.ts for shared identifier-pattern checks.
