The trust boundary of the suite. One validated type per file; the `New*`
constructor is the only admission path for external strings and numbers.

## Summary

- util.ts — the brand machinery (`ValidatedString`, `ValidatedNumber`,
  `newValidated`), `isRecord`, and the shared model-token pattern.
- sessionId.ts — `SessionId`; ids that reach URL path segments.
- featureId.ts — `FeatureId`; ids used as state-file keys and option
  buckets.
- providerId.ts / modelId.ts / modelRef.ts — model tokens and their pair.
- idleTimeoutMs.ts — positive finite durations.
- absolutePath.ts — absolute-path acceptance for environment values.
- featureStates.ts — the toggle map: `FeatureId` keys, boolean values,
  null-prototype by construction.

## Constraints

- Every external value MUST pass a constructor in this directory before it
  reaches business logic, a URL, a file write, or a JSON body.
- Constructors take `unknown` and return `T | undefined`; the caller decides
  whether a rejection stops the flow or is logged.
- MUST NOT use classes; the branded type plus constructor is the value
  object.
- The `as` cast inside a constructor is the one sanctioned breach of the
  brand. A cast anywhere else MUST sit on an authored literal, never on
  input.
- Regular expressions MUST be anchored and bounded.

## Guidance

- A new input kind gets one file, one `New<Type>` constructor, and one
  table-driven test file beside it.
- Shared conversion plumbing goes in util.ts so every constructor stays
  uniform.
