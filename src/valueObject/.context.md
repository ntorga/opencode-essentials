Branded value objects validate external identifiers, numbers, paths, and
configuration data before plugin logic uses them. The idle-timeout value also
provides the shared timer ceiling and clamp for the server compactor and TUI
clock.

## Summary

- absolutePath.ts — accepts absolute filesystem paths.
- absolutePath.test.ts — checks absolute-path acceptance and rejects other
  input shapes.
- contextTokens.ts — validates positive whole token counts up to 2,000,000;
  defines the ceiling presets and default.
- contextTokens.test.ts — checks valid and invalid token counts and preset
  bounds.
- essentialsConfig.ts — parses versioned and legacy state documents, and
  serializes feature states, timeouts, and ceilings.
- essentialsConfig.test.ts — checks parsing, migration, invalid documents,
  and serialization round trips.
- featureId.ts — validates feature identifiers used as state keys and option
  buckets.
- featureId.test.ts — checks accepted and rejected identifier shapes.
- featureStates.ts — validates boolean feature maps and creates a
  null-prototype map.
- featureStates.test.ts — checks that only valid identifier and boolean
  entries remain.
- idleTimeoutMs.ts — validates positive finite durations and defines the
  default, custom-minute limit, timer ceiling, and shared delay clamp.
- idleTimeoutMs.test.ts — checks duration validation and caps a delay above
  the timer ceiling.
- modelId.ts — validates model identifiers with the shared model-token rule.
- modelId.test.ts — checks accepted and rejected model identifier shapes.
- modelRef.ts — validates a host provider/model pair and returns its typed
  project form.
- modelRef.test.ts — checks complete valid pairs and rejects malformed pairs.
- providerId.ts — validates provider identifiers with the shared model-token
  rule.
- providerId.test.ts — checks accepted and rejected provider identifier
  shapes.
- sessionId.ts — validates session identifiers for URL path segments.
- sessionId.test.ts — checks accepted IDs and rejects unsafe path shapes.
- timestampMs.ts — validates epoch milliseconds and rejects values before
  2001.
- timestampMs.test.ts — checks finite epoch-millisecond values and rejects
  seconds-based or implausible timestamps.
- util.ts — defines branded string and number types, shared validation,
  `isRecord`, and the model-token pattern.

## Constraints

- Every external value MUST pass a constructor in this directory before it
  reaches business logic, a URL, a file write, or a JSON body.
- Constructors take `unknown` and return `T | undefined`; the caller decides
  whether a rejection stops the flow or is logged.
- MUST NOT use classes; the branded type plus constructor is the value
  object.
- The `as` cast inside a constructor is the one sanctioned breach of the
  brand. A cast anywhere else MUST sit on an authored literal, never on
  input.
- Regular expressions MUST be anchored and bounded.

## Guidance

- A new input kind gets one file, one `newX` constructor, and one
  table-driven test file beside it.
- Shared string conversion goes in util.ts so every identifier constructor
  uses the same validation path.
