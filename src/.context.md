One OpenCode plugin suite with two entry points. The server entry runs the
features; the TUI companion lets the user toggle each feature at runtime.

## Summary

- server.ts — server entry. Default export `{ id, server }`. Builds each
  feature's hooks from per-feature options and fans them out via
  `combineHooks`.
- tui.ts — TUI entry. Default export `{ id, tui }`. Registers the palette
  command `essentials.features`, which opens a `DialogSelect` to toggle
  features at runtime.
- state.ts — shared toggle protocol. A JSON file at
  `$XDG_DATA_HOME/opencode/essentials.json`. The TUI writes it; the server
  reads it at decision points.
- hooks.ts — `combineHooks`. Fans one hook out to all features.
- log.ts — structured logging through `client.app.log`.
- features/ — the feature suite. Each feature is a `SuiteFeature` entry.
- README.md — installation, configuration, and exact semantics.

## Constraints

- MUST stay dependency-free at runtime. Both entries import types and Node
  built-ins only.
- MUST export either `server()` or `tui()` from a module, never both.
- MUST register the server entry in `opencode.json` and the TUI entry in
  `tui.json`. The two hosts read separate config files; the TUI host never
  loads `opencode.json`.
- MUST NOT require a restart to toggle a feature. The server reads the state
  file at each decision point.
- MUST NOT poll. The compactor is event-driven with one-shot timers.

## Guidance

- Add a new feature as a `SuiteFeature` in `features/` and register it in
  `features/registry.ts`. Both entries pick it up automatically.
- `combineHooks` runs feature handlers sequentially without isolation: one
  feature throwing aborts the rest for that event. Wrap the handler when a
  second feature lands.
