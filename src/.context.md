`src/` holds six host-pinned plugin entries at its root, the shared state
and logging plumbing they call, and four directories: feature logic, parsed
documents, validated single values, and status-bar content. OpenCode loads
the local wrapper guard through `.opencode/plugins/exec-wrapper-guard.ts`.

## Summary

- documents/ — parsed whole payloads: the state file, assistant messages, the auth store entry.
- exec-wrapper-guard.test.ts — tests shell-wrapper parsing and rule decisions.
- exec-wrapper-guard.ts — checks wrapped shell commands against agent rules.
- features/ — feature contracts, implementations, registry, and their shared logic.
- features/autoAllowPolicy.ts — chooses the classifier's reply: `always` only for the edit class, `once` for Bash and everything else.
- hooks.test.ts — tests ordered hook fan-out.
- hooks.ts — combines handlers from server features.
- log.test.ts — tests control-character sanitizing.
- log.ts — sanitizes and writes structured plugin logs.
- openRouterAuth.test.ts — tests stored OpenRouter credentials and fallback behavior.
- openRouterAuth.ts — reads OpenCode's auth store file and resolves the OpenRouter key.
- permission-assistant.tsx — TUI pending-permission listener, notifier, and audit logger; answers a safe verdict through `features/autoAllowPolicy.ts` (only file edits reply `always`), and appends Jev scores and deciding actors to `permission-audit.log` via `features/permissionAudit.ts`.
- reasoning-loop-escalation.tsx — TUI reasoning-loop suspect counter; wakes the human when the loop outlasts the classifier's patience.
- server.test.ts — tests server entry and feature hook setup.
- server.ts — builds and combines server feature hooks.
- state.test.ts — tests shared configuration parsing and persistence.
- state.ts — reads and writes the shared feature configuration file.
- statusBar/ — idle clock, idle anchor, and response metrics for the shared status bar.
- tui.test.ts — tests the feature dialog and its settings.
- tui.ts — registers `/essentials` and manages feature settings.
- usage-status.tsx — registers one padded footer row with idle time first, then the provider health verdict and response metrics.
- valueObject/ — branded single values for external and host-provided data.

## Constraints

- Plugin entry modules MUST export the hook for one host. The suite entries
  export `server` or `tui`; the wrapper guard exports its own plugin.
- Entry paths are pinned by `tui.json`, the documented `opencode.json`, and
  the plugin loader; they MUST stay at `src/` root.
- External strings and numbers MUST pass a constructor in `valueObject/`,
  and whole payloads MUST pass a parser in `documents/`, before they reach
  feature logic.
- Feature changes MUST use the shared state file so toggles take effect
  without restarting OpenCode.
- Compactors MUST remain event-driven and use one-shot timers.
- State writes MUST refuse unreadable or invalid state files.

## Guidance

- Register each feature row in `features/registry.ts`. The server uses rows
  with `buildHooks`; the TUI uses the registry for `/essentials`.
- `combineHooks` runs feature handlers sequentially. A thrown handler stops
  the remaining handlers for that event.
- Keep entries thin: rendering composes data; logic lives in `features/`,
  `statusBar/`, or `documents/`.
