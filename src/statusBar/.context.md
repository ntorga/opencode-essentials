This directory computes the content of the shared status bar: the provider
health verdict, response metrics, the idle-time anchor, and the idle clock
line with its color. The `usage-status.tsx` entry renders the rows these
modules produce.

## Summary

- idleClockStatus.ts — resolves idle clock settings and the active session state.
- idleWaiting.test.ts — tests idle anchors, elapsed time, and display colors.
- idleWaiting.ts — selects and formats the TUI idle-time anchor.
- tone.ts — the shared good/muted/warning/error tone vocabulary and its theme mapping.
- usageStatus.test.ts — tests response selection, timing, rates, health grades, tones, and formatting.
- usageStatus.ts — validates and formats completed-response metrics and the five-minute health verdict; slow values and troubled streaks carry tones.

## Constraints

- Rendering lives in the entries; these modules return plain data and strings.
- External values MUST pass valueObject constructors or document parsers
  before these modules use them.
- Status-bar text colors come only from the `tone.ts` vocabulary, so the
  clock and the metrics share one good/muted/warning/error mapping.

## Guidance

- Read the response window through `../documents/completedAssistantMessage.ts`
  instead of probing raw payloads.
- The verdict and the metrics share one window pass
  (`windowResponseTimings`); grading derives from the tone functions, so a
  threshold change has exactly one home.
