This directory defines six feature rows for the essentials plugin and the
shared logic those rows call. Server features provide hooks; TUI-only
features provide metadata for the feature dialog and their separate TUI
entries.

## Summary

- autoAllowPolicy.ts — chooses `always` only for the edit class, `once` for bash and every other permission.
- autoAllowPolicy.test.ts — tests the edit-only always gate.
- contextCeiling.test.ts — tests turn measurement and model-window limits.
- contextCeiling.ts — measures completed turns and clamps token ceilings.
- feature.ts — defines suite feature contracts and feature context.
- hostEventRejections.ts — shared warn line for a rejected host id.
- idle-auto-compactor.test.ts — tests timer lifecycle, gates, skips, and failures.
- idle-auto-compactor.ts — server feature that compacts idle sessions.
- idle-clock.ts — TUI-only feature row for the idle clock.
- notificationText.test.ts — tests markup escaping and end-of-options handling.
- notificationText.ts — builds notify-send arguments and escapes the body.
- permission-assistant.ts — feature row for permission decisions and notifications.
- permissionDecision.test.ts — tests classifier response validation and threshold.
- permissionDecision.ts — classifier questions (permission safety, reasoning spiral) and the shared Decisions API request.
- reasoning-loop-guard.test.ts — tests spiral detection, confirmation, interrupts, budgets, and escalation.
- reasoning-loop-guard.ts — server feature that cancels confirmed reasoning spirals and sends a correction.
- registry.ts — lists six rows for server hooks and TUI controls.
- requestDeadline.ts — defines deadlines for local OpenCode server requests.
- sessionSummarizer.ts — shares the session summary request between compactors.
- token-ceiling-compactor.test.ts — tests idle checks, limits, and failures.
- token-ceiling-compactor.ts — server feature that compacts at a token ceiling.
- usage-status.ts — feature row that toggles response metrics in the shared status bar.

## Constraints

- TUI-only feature rows MUST omit `buildHooks`; server setup skips rows without it.
- Server feature handlers MUST read the shared feature state at decision points.
- Compactor behavior MUST remain event-driven; idle timers are one-shot.
- Session IDs MUST pass `newSessionId` before client API calls.

## Guidance

- Define a feature row here and register it in `registry.ts`.
- Keep feature-specific behavior in its own module.
