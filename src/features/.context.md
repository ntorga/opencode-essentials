The feature suite of the essentials plugin. Each feature is a self-contained
`SuiteFeature`; the registry lists them for every entry point. A server
feature also carries `buildHooks`; a TUI-only feature omits it and the server
skips it.

## Summary

- feature.ts — the `SuiteFeature` and `ServerSuiteFeature` contracts plus
  `FeatureContext`. `buildHooks` is optional on `SuiteFeature` and required
  on `ServerSuiteFeature`.
- registry.ts — the `FEATURES` list. `server.ts` reads it to build hooks and
  `tui.ts` reads it for the dialog rows. The clock entry itself is imported
  by `idle-clock.tsx` directly.
- idle-auto-compactor.ts — feature 1 (a `ServerSuiteFeature`). Compacts a
  session after continuous idle via `session.summarize`. Its state machine
  absorbs the compaction busy/idle echoes. Gated on the state file's master
  switch and its own flag; the idle timeout comes from the state file, else
  the plugin option.
- idle-clock.ts — feature 2 (TUI-only, no `buildHooks`). Its metadata feeds
  the `/essentials` row; the state-file flag and master switch gate the
  render in `idle-clock.tsx`.
- idle-auto-compactor.test.ts — tests for the compactor.

## Constraints

- MUST stay dependency-free at runtime. Imports are types and Node built-ins
  only.
- MUST gate each feature on the state file: the master switch first, then the
  per-feature flag. The server reads the file at decision points.
- MUST NOT poll. The compactor is event-driven with one-shot timers. (The
  clock's 1-second tick drives a visible countdown, not a wait for events.)
- MUST NOT let an `await` sit between a guard check and the assignment it
  protects. Two idle events for one session could otherwise both pass the
  guard and both arm a timer; the second arm orphans the first, and the
  orphan still compacts.
- MUST NOT pass an event-payload session id to a client call unchecked. The
  id reaches a URL path segment; build it with `newSessionId` from
  `../valueObject/sessionId.ts`.

## Guidance

- Add a feature as a new file exporting a `SuiteFeature`, then register it in
  `registry.ts`. Keep each feature self-contained.
