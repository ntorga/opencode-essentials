The feature suite of the essentials plugin. Each feature is a self-contained
`SuiteFeature`; the registry lists them for every entry point. A server
feature also carries `buildHooks`; a TUI-only feature omits it and the server
skips it.

## Summary

- feature.ts — the `SuiteFeature` and `ServerSuiteFeature` contracts plus
  `FeatureContext`. `buildHooks` is optional on `SuiteFeature` and required
  on `ServerSuiteFeature`.
- registry.ts — the `FEATURES` list. `server.ts` reads it to build hooks and
  `tui.ts` reads it for the dialog rows. The clock entry itself is imported
  by `idle-clock.tsx` directly.
- idle-auto-compactor.ts — feature 1 (a `ServerSuiteFeature`). Compacts a
  session after continuous idle via `session.summarize`. It skips when the
  last message is a summary or has a compaction part, or the newest completed
  turn uses under 32,000 tokens. It uses that turn's model and disables
  continuation. If assistant messages exist but no measurable turn is
  available, it logs `IdleCompactionTurnRejected` and skips. Its state machine
  absorbs compaction status echoes. The state file's master switch and feature
  flag gate it; its timeout overrides the plugin option. The server timer and
  TUI clock share the ceiling from `../valueObject/idleTimeoutMs.ts`.
- token-ceiling-compactor.ts — feature 2 (a `ServerSuiteFeature`). On an
  idle `session.status` event it measures the newest real turn (via
  `../contextCeiling.ts`), clamps the stored ceiling to the model's context
  window, and compacts through `sessionSummarizer.ts` with continuation
  enabled. It checks once per settled idle period; a genuine prompt reopens
  the period.
- sessionSummarizer.ts — the shared `session.summarize` request with its
  deadline and error mapping, used by both compactors. The caller selects
  continuation: idle compaction disables it and token-ceiling compaction
  enables it. Each caller maps the result to its own log keys.
- idle-clock.ts — feature 3 (TUI-only, no `buildHooks`). Its metadata feeds
  the `/essentials` row; the state-file flag and master switch gate the
  render in `idle-clock.tsx`.
- idle-auto-compactor.test.ts — checks timer lifecycle, feature gates,
  compaction skips, timeout clamps, and failures.
- token-ceiling-compactor.test.ts — checks idle-period checks, model-window
  clamps, continuation, and failure handling.

## Constraints

- MUST stay dependency-free at runtime. Imports are types and Node built-ins
  only.
- MUST gate each feature on the state file: the master switch first, then the
  per-feature flag. The server reads the file at decision points.
- MUST NOT poll. The compactor is event-driven with one-shot timers; the
  ceiling compactor runs once per idle event, at most one check per period. (The clock's 1-second tick
  drives a visible countdown, not a wait for events.)
- MUST NOT let an `await` sit between a guard check and the assignment it
  protects. Two idle events for one session could otherwise both pass the
  guard and both arm a timer — or both run a ceiling check; the second arm
  orphans the first, and the orphan still compacts.
- MUST NOT pass an event-payload session id to a client call unchecked. The
  id reaches a URL path segment; build it with `newSessionId` from
  `../valueObject/sessionId.ts`.

## Guidance

- Add a feature as a new file exporting a `SuiteFeature`, then register it in
  `registry.ts`. Keep each feature self-contained.
