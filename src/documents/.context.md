Parsed documents are packaged information that crosses a boundary: a JSON
file written elsewhere, or an event payload handed over by OpenCode. Each
module owns one external format — its keys, version, and rejection rules —
and exports a branded type no caller can build without the parser. Value
objects validate single values; documents validate whole payloads.

## Summary

- completedAssistantMessage.ts — validates a finished assistant message
  payload for the response window.
- essentialsDocument.ts — parses and serializes the shared state file,
  including the legacy migration; exports EssentialsConfig.
- openRouterCredential.ts — reads the OpenRouter entry of OpenCode's auth
  store document; reports absent, valid, or invalid.
- util.ts — the ParsedDocument brand and the cast factory only parsers call.

## Constraints

- Every exported document type MUST be branded through util.ts; hand-built
  literals of a document shape MUST NOT type-check.
- A parser trusts nothing: it reads `unknown` field by field and returns
  `undefined` or a rejection status for a half-interpretable document.
- A document module MUST NOT touch the filesystem or network; callers read
  bytes and pass parsed JSON in.
- Changing a key, version, or shape here is a file-format change; keep the
  serialization round-trip tests green.

## Guidance

- Name the parse and serialize functions after the document, not the domain
  type, so the storage coupling is visible: `parseEssentialsDocument`.
- Keep single-value rules in `../valueObject/`; a document composes those
  constructors.
